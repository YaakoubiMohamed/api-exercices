🔧 inject() - Injection de Dépendances Moderne

❌ Ancienne Méthode (Constructor)

export class FootballService {

    private readonly http: HttpClient
  ) {}

  • ✗ Constructeur encombré si beaucoup de dépendances
  • ✗ Moins lisible avec 5+ services
  • ✗ Impossible hors des classes

✅ Nouvelle Méthode Angular 14+ (inject)

export class FootballService {
  
  // inject() au niveau de la propriété
  private readonly http = inject(HttpClient);
  
  getStandings(): Observable<Response> {
    return this.http.get<Response>(url);
  }
}
  • ✓ Plus propre et concis
  • ✓ Type inféré automatiquement
  • ✓ Utilisable dans les fonctions/guards
  • ✓ Recommandé par Angular Team

📦 Service Complet avec inject()

// football.service.ts
import { Injectable, inject } from '@angular/core';
import { HttpClient, HttpHeaders } from '@angular/common/http';

@Injectable({ providedIn: 'root' })
export class FootballService {
  
  // ✅ Injection moderne avec inject()
  private readonly http = inject(HttpClient);
  
  private readonly API_KEY = '9be36b8187f24de0951f540fb962b655';
  private readonly headers = new HttpHeaders({
    'X-Auth-Token': this.API_KEY
  });
  
  getStandings(code: string): Observable<StandingsResponse> {
    const url = `/api/football/competitions/${code}/standings`;
    return this.http.get<StandingsResponse>(url, { headers: this.headers });
  }
}

💡 Pourquoi inject() est mieux ?

  • Lisibilité : Pas de constructeur massif
  • Flexibilité : Fonctionne dans les guards, resolvers, fonctions
  • Type Safety : TypeScript infère le type
  • Future-proof : Aligné avec la direction d'Angular

🚀 Signals - Gestion d'État Réactive

❌ Ancienne Méthode (Properties)

export class FootballComponent {
  
  standings: Standing[] = [];
  loading: boolean = false;
  
  loadData() {
    this.loading = true;
    this.service.getData()
      .subscribe(data => {
        // Assigner directement
        this.standings = data;
        this.loading = false;
      });
  }
}

Problème : Zone.js vérifie TOUT le composant à chaque changement

✅ Nouvelle Méthode Angular 16+ (Signals)

export class FootballComponent {
  
  // Signals = Conteneurs réactifs
  readonly standings = signal<Standing[]>([]);
  readonly loading = signal(false);
  
  loadData() {
    this.loading.set(true);
    this.service.getData()
      .subscribe(data => {
        // Mise à jour via .set()
        this.standings.set(data);
        this.loading.set(false);
      });
  }
}

Avantage : Angular met à jour UNIQUEMENT ce qui utilise ce signal

🎯 Les 3 Opérations sur les Signals

// 1️⃣ CRÉATION : signal(valeurInitiale)
readonly count = signal(0);
readonly users = signal<User[]>([]);

// 2️⃣ LECTURE : appeler comme une fonction ()
console.log(this.count());  // Affiche : 0
const value = this.count(); // Lit la valeur

// Template
@if (loading()) { ... }  // Parenthèses obligatoires!
@for (team of standings(); track team.id) { ... }

// 3️⃣ MISE À JOUR :
// .set() = Remplacer complètement
this.count.set(10);
this.users.set(newUserArray);

// .update() = Modifier basé sur la valeur actuelle
this.count.update(n => n + 1);  // Incrémente
this.users.update(list => [...list, newUser]);  // Ajoute

✨ Pourquoi Signals est Révolutionnaire ?

  • ⚡ Performance : Fine-grained reactivity (mise à jour ciblée)
  • 🎯 Simplicité : Pas besoin de OnPush, markForCheck()
  • 🔒 Immutabilité : readonly empêche les modifications externes
  • 🧠 Prévisibilité : Flux de données unidirectionnel clair
  • 🚀 Future : Préparation pour Zoneless Angular
