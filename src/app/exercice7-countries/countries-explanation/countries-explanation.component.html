📚 Exercice 7 - Explication Détaillée

Path Parameters et gestion d'état avec Signals (Angular 20)

🎯 Objectif de l'exercice

Créer une application Angular pour rechercher et afficher des informations sur les pays du monde en utilisant l'API REST Countries avec des Path Parameters.

API utilisée: REST Countries
URL de base: https://restcountries.com/v3.1
Authentification: ❌ Aucune clé API requise !
Concept clé: 🔗 Path Parameters (paramètres dans l'URL)

🔗 Qu'est-ce qu'un Path Parameter?

  • Path Parameter: Valeur dynamique intégrée directement dans le chemin de l'URL. Contrairement aux Query Parameters (?key=value), les Path Parameters font partie du chemin lui-même.
    Exemple: /name/france → 'france' est le path parameter.
    Utilisé quand le paramètre identifie une ressource spécifique (pays, utilisateur, produit).
  • Endpoints de l'exercice:
    • /v3.1/name/{name} → Recherche par nom
    • /v3.1/region/{region} → Filtre par région
    • /v3.1/all → Tous les pays

🏗️ Architecture Angular 20

📐 Pattern moderne utilisé dans cet exercice:

  • inject(): Nouvelle injection de dépendances fonctionnelle (remplace constructor). Plus concis, plus lisible, et compatible avec les fonctions standalone.
  • signal(): Gestion d'état réactive native Angular (remplace les propriétés simples). Détection de changement automatique et optimisée, plus performant que Zone.js.
  • @if / @for: Nouveau control flow Angular 17+ (remplace *ngIf / *ngFor). Syntaxe plus claire, meilleure performance, et typage amélioré.
  • standalone: true: Composants autonomes sans NgModule. Architecture simplifiée, tree-shaking optimal, imports explicites.

📝 Étape 2: Créer les interfaces (Models)

// country.model.ts
export interface Country {
  name: {
    common: string;      // Nom commun (ex: "France")
    official: string;    // Nom officiel (ex: "French Republic")
  };
  capital?: string[];    // Capitale(s) - optionnel car certains pays n'en ont pas
  population: number;    // Population
  area: number;          // Superficie en km²
  region: string;        // Région (ex: "Europe")
  subregion?: string;    // Sous-région (ex: "Western Europe")
  flags: {
    png: string;         // URL du drapeau PNG
    svg: string;         // URL du drapeau SVG (meilleure qualité)
    alt?: string;        // Texte alternatif pour accessibilité
  };
  languages?: {          // Langues parlées (clés dynamiques)
    [key: string]: string;
  };
  maps: {
    googleMaps: string;  // Lien Google Maps
  };
}

🔑 Mots-clés TypeScript détaillés:

  • interface: Définit un contrat de structure pour les objets TypeScript.
    Pourquoi l'utiliser? Garantit que les données API correspondent à la structure attendue. TypeScript vérifiera à la compilation que vous accédez uniquement aux propriétés définies. Permet l'autocomplétion VS Code: tapez 'country.' et voyez toutes les propriétés disponibles. Les erreurs de typo sont détectées immédiatement: country.naem génère une erreur.
  • ? (propriété optionnelle): Indique qu'une propriété peut exister ou être undefined.
    Pourquoi l'utiliser? L'API REST Countries ne retourne pas toujours toutes les propriétés. Exemple: capital?: string[] car certains pays (comme l'Antarctique) n'ont pas de capitale. Vous devez vérifier son existence avant utilisation: country.capital?.[0] retourne undefined si absent. Sans le '?', TypeScript générerait une erreur si la propriété est absente dans les données.
  • [key: string]: string (Index Signature): Objet avec clés dynamiques inconnues à l'avance.
    Pourquoi l'utiliser? Les langues varient selon le pays: { "fra": "French", "eng": "English" }. Les codes de langue (fra, eng, deu) sont différents pour chaque pays et inconnus à la compilation. Permet de modéliser des structures JSON flexibles sans énumérer toutes les possibilités. Itération avec Object.keys(country.languages) ou Object.values(country.languages).
  • string[] (tableau typé): Tableau contenant uniquement des chaînes de caractères.
    Pourquoi l'utiliser? Type-safety: TypeScript refusera capitals.push(123). Accès au premier élément: capital[0] avec autocomplétion sur les méthodes de String. Alternative: Array<string> est équivalent mais string[] est plus concis et idiomatique.

🔧 Étape 3: Créer le Service HTTP (Angular 20)

// country.service.ts
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable, of } from 'rxjs';
import { catchError } from 'rxjs/operators';

@Injectable({ providedIn: 'root' })
export class CountryService {
  // ✅ Angular 20: inject() remplace constructor injection
  private readonly http = inject(HttpClient);
  
  private readonly BASE_URL = 'https://restcountries.com/v3.1';

  // Recherche avec PATH PARAMETER: /name/{name}
  searchByName(name: string): Observable<Country[]> {
    return this.http.get<Country[]>(
      `${this.BASE_URL}/name/${name}`  // Path parameter!
    ).pipe(
      catchError(() => of([]))  // Retourne tableau vide si erreur
    );
  }

  // Filtre avec PATH PARAMETER: /region/{region}
  getByRegion(region: string): Observable<Country[]> {
    return this.http.get<Country[]>(
      `${this.BASE_URL}/region/${region}`
    ).pipe(
      catchError(() => of([]))
    );
  }

  // Obtenir tous les pays: /all
  getAllCountries(): Observable<Country[]> {
    return this.http.get<Country[]>(
      `${this.BASE_URL}/all`
    ).pipe(
      catchError(() => of([]))
    );
  }
}

🔑 Mots-clés détaillés:

  • inject(HttpClient): Nouvelle fonction d'injection de dépendance Angular 14+.
    Pourquoi l'utiliser? Plus concis que constructor(private http: HttpClient). Fonctionne dans les fonctions standalone, pas seulement les classes. Code plus lisible: toutes les dépendances groupées en haut de la classe. Recommandé par l'équipe Angular pour les nouvelles applications.
    Avant: constructor(private readonly http: HttpClient) {}
    Après: private readonly http = inject(HttpClient);
  • `${this.BASE_URL}/name/${name}` (Template Literal + Path Parameter):
    Pourquoi l'utiliser? Construit une URL dynamique proprement. Le path parameter 'name' est directement intégré dans l'URL: /name/france. Plus lisible que la concaténation: this.BASE_URL + '/name/' + name. L'URL finale ressemble à: https://restcountries.com/v3.1/name/france
  • pipe(): Méthode pour chaîner des opérateurs RxJS sur un Observable.
    Pourquoi l'utiliser? Permet d'appliquer des transformations séquentiellement. Chaque opérateur reçoit le résultat du précédent: source.pipe(op1, op2, op3). Style fonctionnel: ne modifie pas l'Observable original, retourne un nouvel Observable. Essentiel pour la composition: map → filter → catchError → tap.
  • catchError(() => of([])): Opérateur RxJS pour gérer les erreurs gracieusement.
    Pourquoi l'utiliser? Si l'API retourne 404 (pays non trouvé), on retourne un tableau vide. L'application ne plante pas, l'utilisateur voit simplement "Aucun résultat". of([]) crée un Observable qui émet un tableau vide puis se complete. Alternative: catchError(err => throwError(() => new Error('Custom message'))).
  • of([]): Fonction RxJS créant un Observable à partir d'une valeur.
    Pourquoi l'utiliser? catchError doit retourner un Observable, pas une valeur simple. of([]) crée un Observable qui émet [] puis se complete immédiatement. Autres usages: of(null), of({default: 'value'}), of(1, 2, 3) pour plusieurs émissions.
  • Observable<Country[]>: Type de retour représentant un flux asynchrone de données.
    Pourquoi l'utiliser? TypeScript sait que le subscribe recevra un Country[]. Autocomplétion: .subscribe(countries => countries.map(c => c.name.common)). Le <T> générique garantit le type des données émises par l'Observable.

🏠 Étape 4: Composant principal avec Signals (Angular 20)

// countries.component.ts
import { Component, inject, signal } from '@angular/core';
import { FormsModule } from '@angular/forms';
import { RouterLink } from '@angular/router';
import { DecimalPipe } from '@angular/common';
import { CountryService } from '../services/country.service';
import { Country } from '../models/country.model';

@Component({
  selector: 'app-countries',
  standalone: true,
  imports: [FormsModule, RouterLink, DecimalPipe],
  templateUrl: './countries.component.html',
  styleUrl: './countries.component.css'
})
export class CountriesComponent {
  // ✅ Angular 20: inject() au lieu de constructor
  private readonly countryService = inject(CountryService);
  
  // ✅ Angular 16+: Signals pour l'état réactif
  readonly countries = signal<Country[]>([]);
  readonly loading = signal(false);
  readonly error = signal<string | null>(null);
  readonly hasSearched = signal(false);
  readonly searchTerm = signal('');
  
  // Liste des régions (constante readonly)
  readonly regions = ['Africa', 'Americas', 'Asia', 'Europe', 'Oceania'] as const;
  
  // Mettre à jour le signal depuis l'input
  onSearchInput(event: Event): void {
    const input = event.target as HTMLInputElement;
    this.searchTerm.set(input.value);
  }
  
  search(): void {
    const term = this.searchTerm();  // Lire la valeur du signal
    if (!term.trim()) return;
    
    this.loading.set(true);     // Mettre à jour le signal
    this.error.set(null);
    this.hasSearched.set(true);
    
    this.countryService.searchByName(term).subscribe({
      next: (data) => {
        this.countries.set(data);  // ✅ .set() remplace la valeur
        this.loading.set(false);
      },
      error: () => {
        this.error.set('Erreur lors de la recherche');
        this.countries.set([]);
        this.loading.set(false);
      }
    });
  }
  
  filterByRegion(event: Event): void {
    const select = event.target as HTMLSelectElement;
    const region = select.value;
    
    if (!region) {
      this.countries.set([]);
      return;
    }
    
    this.loading.set(true);
    
    this.countryService.getByRegion(region).subscribe({
      next: (data) => {
        this.countries.set(data);
        this.loading.set(false);
      },
      error: () => {
        this.error.set('Erreur lors du filtrage');
        this.loading.set(false);
      }
    });
  }
  
  // Helper pour extraire les langues
  getLanguages(country: Country): string[] {
    if (!country.languages) return [];
    return Object.keys(country.languages).map(key => country.languages![key]);
  }
}

🔑 Signals Angular - Concepts détaillés:

  • signal<T>(initialValue): Crée un signal réactif typé avec une valeur initiale.
    Pourquoi l'utiliser? Remplace les propriétés simples pour une gestion d'état réactive. Détection de changement automatique: Angular sait exactement quand le signal change. Plus performant que Zone.js: pas de vérification de tout l'arbre de composants.
    Syntaxe: signal<Country[]>([]) crée un signal initialisé avec un tableau vide. Le type générique <T> garantit le type-safety sur toutes les opérations.
  • .set(newValue): Remplace complètement la valeur du signal.
    Pourquoi l'utiliser? Modification directe quand vous avez la nouvelle valeur complète.
    Exemple: this.countries.set(data) remplace tout le tableau.
    Exemple: this.loading.set(true) change le booléen. Angular détecte ce changement et re-rend uniquement les vues qui utilisent ce signal.
  • .update(fn): Met à jour la valeur basée sur la valeur actuelle.
    Pourquoi l'utiliser? Quand la nouvelle valeur dépend de l'ancienne.
    Exemple: this.count.update(n => n + 1) incrémente le compteur.
    Exemple: this.items.update(list => [...list, newItem]) ajoute un élément. Pattern fonctionnel: la fonction reçoit la valeur actuelle et retourne la nouvelle.
  • signal() (lecture): Appeler le signal comme une fonction pour lire sa valeur.
    Pourquoi cette syntaxe? Distingue clairement lecture et écriture.
    Lecture: const term = this.searchTerm() retourne 'france'.
    Template: {{ countries() }} affiche la valeur actuelle. Angular track ces lectures pour savoir quelles vues dépendent de quels signals.
  • as const: Assertion TypeScript qui rend un tableau ou objet en lecture seule et littéral.
    Pourquoi l'utiliser? ['Africa', 'Europe'] as const crée un tuple immuable. TypeScript infère le type ('Africa' | 'Americas' | 'Asia' | 'Europe' | 'Oceania')[] au lieu de string[]. Empêche les modifications accidentelles: regions.push('Invalid') génère une erreur. Parfait pour les constantes de configuration ou les listes de valeurs permises.
  • inject(Service): Injection de dépendance fonctionnelle (Angular 14+).
    Pourquoi l'utiliser? Plus concis que constructor(private service: Service). Fonctionne en dehors des constructeurs (fonctions, guards, etc.). Toutes les dépendances groupées visuellement en haut de la classe.
    Avant: constructor(private readonly countryService: CountryService) {}
    Après: private readonly countryService = inject(CountryService);
  • Object.keys() + map(): Technique pour transformer un objet en tableau.
    Pourquoi l'utiliser? languages est un objet {fra: 'French', eng: 'English'}. Object.keys(languages) retourne ['fra', 'eng']. .map(key => languages[key]) retourne ['French', 'English']. Le '!' dans languages![key] indique à TypeScript que languages existe (nous avons vérifié avant).

🔧 Étape 5: RxJS - catchError et gestion d'erreurs

// Dans le service: Gestion d'erreur centralisée
import { catchError } from 'rxjs/operators';
import { of } from 'rxjs';

searchByName(name: string): Observable<Country[]> {
  return this.http.get<Country[]>(`${this.BASE_URL}/name/${name}`)
    .pipe(
      catchError((error) => {
        console.error('Erreur API:', error);
        return of([]);  // Retourne un tableau vide en cas d'erreur
      })
    );
}

// Dans le composant: Subscribe simple grâce à catchError
search(): void {
  this.loading.set(true);
  
  this.countryService.searchByName(term).subscribe({
    next: (data) => {
      this.countries.set(data);
      this.loading.set(false);
      // Si data est vide, c'est que l'erreur a été gérée dans le service
    },
    error: () => {
      // Ce bloc n'est jamais atteint grâce à catchError
      this.error.set('Erreur inattendue');
      this.loading.set(false);
    }
  });
}

🔑 Concepts RxJS détaillés:

  • catchError(): Opérateur RxJS qui intercepte les erreurs et permet de les gérer.
    Pourquoi l'utiliser dans le service? Centralise la gestion d'erreurs en un seul endroit. Le composant n'a pas besoin de gérer chaque erreur individuellement. Retourne un Observable de remplacement: of([]) fournit un tableau vide au lieu de l'erreur. L'application continue de fonctionner sans planter.
  • of(value): Crée un Observable qui émet une valeur immédiatement puis complete.
    Pourquoi l'utiliser? catchError doit retourner un Observable, pas une valeur simple. of([]) crée un Observable émettant un tableau vide. Le subscribe recevra [] dans 'next', pas dans 'error'. Alternative: throwError() pour propager l'erreur au composant.
  • pipe(): Méthode pour chaîner des opérateurs RxJS.
    Pourquoi l'utiliser? Compose plusieurs transformations de manière lisible. .pipe(map(...), filter(...), catchError(...)) applique les opérateurs en séquence. Style fonctionnel: chaque opérateur retourne un nouvel Observable. Plus maintenable que les callbacks imbriqués.
  • Observable: Flux de données asynchrones pouvant émettre 0, 1 ou plusieurs valeurs.
    Pourquoi l'utiliser? Plus puissant que les Promises pour les opérations asynchrones. Annulable via unsubscribe() (contrairement aux Promises). Composable avec des opérateurs (map, filter, merge, etc.). Parfait pour les événements (clics, WebSocket) et les requêtes HTTP.
  • subscribe(): Active l'Observable et commence à recevoir les valeurs.
    Pourquoi l'utiliser? Un Observable est 'lazy': rien ne se passe sans subscribe(). Le callback 'next' reçoit chaque valeur émise. Le callback 'error' reçoit l'erreur si non gérée par catchError. Le callback 'complete' est appelé quand le flux se termine normalement.

⚡ Flux de données avec catchError:

API Call → Succès → Observable émet Country[] → subscribe.next() → Affichage
                                    ↓
            Erreur 404 → catchError() intercepte
                                    ↓
                         of([]) émet [] → subscribe.next() → "Aucun résultat"

📄 Étape 6: Template avec Signals et Control Flow

<!-- Input avec Signals (pas ngModel) -->
<input 
  type="text"
  [value]="searchTerm()"
  (input)="onSearchInput($event)"
  (keyup.enter)="search()"
  placeholder="Rechercher un pays..."
/>
<button (click)="search()" [disabled]="loading()">🔍 Rechercher</button>

<!-- Filtre par région -->
<select (change)="filterByRegion($event)">
  <option value="">Toutes les régions</option>
  @for (region of regions; track region) {
    <option [value]="region">{{ region }}</option>
  }
</select>

<!-- États conditionnels avec @if -->
@if (loading()) {
  <div class="loading">⏳ Recherche en cours...</div>
}

@if (error()) {
  <div class="error">❌ {{ error() }}</div>
}

<!-- Résultats avec @for -->
@if (!loading() && countries().length > 0) {
  <h2>📋 Résultats ({{ countries().length }} pays)</h2>
  <div class="grid">
    @for (country of countries(); track country.name.common) {
      <div class="card">
        <img [src]="country.flags.svg" [alt]="country.name.common + ' flag'" />
        <h3>{{ country.name.common }}</h3>
        
        @if (country.capital && country.capital.length > 0) {
          <p>🏛️ {{ country.capital[0] }}</p>
        }
        
        <p>👥 {{ country.population | number }}</p>
        <p>📍 {{ country.region }}</p>
        
        @if (country.languages) {
          <div class="languages">
            @for (lang of getLanguages(country); track lang) {
              <span class="tag">{{ lang }}</span>
            }
          </div>
        }
        
        <a [href]="country.maps.googleMaps" target="_blank">🗺️ Voir sur Maps</a>
      </div>
    }
  </div>
}

🔑 Mots-clés du template détaillés:

  • [value]="searchTerm()": Property binding avec lecture de signal.
    Pourquoi l'utiliser? Lie la valeur de l'input au signal searchTerm. searchTerm() appelle le signal pour lire sa valeur actuelle. Contrairement à [(ngModel)], c'est unidirectionnel (signal → input seulement). L'event (input) gère le sens inverse (input → signal).
  • (input)="onSearchInput($event)": Event binding pour chaque caractère tapé.
    Pourquoi l'utiliser? Capture l'événement à chaque frappe, pas seulement à la fin. $event contient l'objet Event natif du navigateur. onSearchInput extrait la valeur et met à jour le signal avec .set(). Alternative: (change) ne se déclenche qu'à la perte de focus.
  • (keyup.enter)="search()": Event binding pour la touche Entrée uniquement.
    Pourquoi l'utiliser? UX améliorée: lance la recherche sans cliquer. Syntaxe Angular: (keyup.TOUCHE) filtre sur une touche spécifique. Autres: (keyup.escape), (keydown.ctrl.s), (keyup.arrowdown). Plus simple que de vérifier event.key === 'Enter' manuellement.
  • @if (loading()): Nouveau control flow Angular 17+ pour conditions.
    Pourquoi l'utiliser? Remplace *ngIf avec une syntaxe plus claire. loading() lit la valeur du signal (true/false). Le bloc est affiché uniquement si la condition est vraie. Plus performant: Angular optimise mieux le rendu conditionnel.
  • @for (item of items(); track item.id): Nouvelle boucle Angular 17+.
    Pourquoi l'utiliser? Remplace *ngFor avec typage amélioré. 'track' est obligatoire: identifiant unique pour optimiser les mises à jour. countries() appelle le signal pour obtenir le tableau actuel. Quand le signal change, seuls les éléments modifiés sont re-rendus.
  • track country.name.common: Identifiant unique pour chaque élément.
    Pourquoi l'utiliser? Angular utilise cette clé pour le DOM diffing. Quand les données changent, Angular compare les clés pour savoir quoi re-rendre. Sans track: Angular recrée tous les éléments à chaque changement. Avec track: seuls les nouveaux/modifiés/supprimés sont touchés. Performance x10!
  • | number: Pipe de formatage pour les nombres.
    Pourquoi l'utiliser? Affiche 67000000 comme '67,000,000' ou '67 000 000'. Ajoute les séparateurs de milliers selon la locale. Paramétrable: | number:'1.0-2' pour 0-2 décimales. Autres pipes: | date, | currency, | percent, | uppercase.
  • [disabled]="loading()": Property binding dynamique sur attribut.
    Pourquoi l'utiliser? Désactive le bouton pendant le chargement. loading() retourne true/false, le bouton est disabled/enabled en conséquence. Empêche les clics multiples pendant une requête en cours. UX: indique visuellement que l'action est en cours.
